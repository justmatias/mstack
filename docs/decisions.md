# Decisions

Decisions taken while executing `PLAN.md` that were not covered by `docs/design.md` or the plan, and adaptations of items marked **[VERIFY]**. Newest last.

| # | Phase | Decision | Reason |
| --- | --- | --- | --- |
| 1 | 0 | All tools are invoked as `uv run ast-grep ...`, never as `sg`. | On many Linux systems `sg` is the shadow-utils `setgroups` binary (it is on this machine: `/usr/bin/sg`). |
| 2 | 0 | `pre-commit` is a dev dependency managed by `uv`, not a global install. | `make setup` must work on a fresh machine with only `uv`. |
| 3 | 0 | `[tool.uv] package = false`: the repo is not an installable package; `example_app` is imported from the repo root. | Simplest option; `lint-imports` and `pytest` run from the root. |
| 4 | 1 | Verified the Cursor rule format: `.mdc` files under `.cursor/rules/` with `description`, `globs`, `alwaysApply` frontmatter (cursor.com/docs/context/rules). Unchanged from the plan. | [VERIFY] item. |
| 5 | 1 | `naming.mdc` has no file in `demo/violations/`. `domain_imports_infra.py` is not expected to produce an ast-grep finding; it is verified by the import-linter test instead. | Judgment rules have no deterministic check, and the architecture rule is enforced by import-linter, not ast-grep. |
| 6 | 2 | Verified Python node names with `--debug-query`: a bare `except:` is an `except_clause` without a `value` field; `except Exception as e:` has `value: as_pattern`. ast-grep does not accept regex in `kind`, so "has a value" is written as `has: {field: value, regex: "."}`. | [VERIFY] item. |
| 7 | 2 | `ast-grep test` runs with `--skip-snapshot-tests`. Valid cases must not match and invalid cases must match; label snapshots are not stored. | Snapshots pin highlight ranges, not behavior, and every generated check would need a regenerated snapshot. Verified that a non-matching invalid case still fails. |
| 8 | 2 | `files`/`ignores` globs are matched against the path exactly as passed on the command line (relative to the cwd; absolute paths do not match `example_app/**`). Rules use `**/<folder>/**` globs so both relative and absolute paths (as sent by agent hooks) match. | Verified with ast-grep 0.51.3. |
| 9 | 2 | `no-print-in-app` is scoped to `**/example_app/**` and `**/demo/**`. | `demo/violations/print_debug.py` stands in for application code; without the second glob the demo could not show the rule. |
| 10 | 2 | `no-manual-init-boilerplate` ships as `warning` and is deliberately narrow: classes whose only method is `__init__`, whose `__init__` only contains `self.x = x` (and comments), and that do not subclass an `*Exception`/`*Error`. Broader detection (e.g. classes with other methods, `self.x = x` mixed with logic) is a Fixit candidate. | Dependency-injection constructors (`self.client = client` plus methods) are legitimate and very common; matching them would be a false positive. |
| 11 | 2 | The `domain_imports_infra.py` test copies `example_app/` and `.importlinter` into a pytest `tmp_path` and adds the demo file there, instead of writing into the real `example_app/domain/`. | Same check, without the risk of leaving a broken file in the working tree if the test is interrupted. |
| 12 | 3 | Verified `ast-grep-ignore` for Python: `# ast-grep-ignore: <id>[, <id>]` on the line directly above the code, or trailing on the same line. A bare `# ast-grep-ignore` suppresses every rule, so `check_exceptions.py` rejects it. The `# rule-exception:` comment goes on the line above (above the code line for the trailing form). Comments are found with `tokenize`, so strings that contain the marker are not mistaken for exceptions. | [VERIFY] item. ast-grep also reports `unused-suppression` for an ignore that suppresses nothing. |
| 13 | 3 | **`scripts/check_language.py` was dropped at the user's request.** English-only (principle 1) is enforced as an explicit instruction in every skill, reference and reviewer template, not as a script. `make lint-rules` does not run a language check. | User decision: a heuristic test is not needed; the agent follows the instruction. |
| 14 | 3 | `check_no_domain_leak.py` takes `--exclude <folder>` (repeatable) for tooling code that is not the analyzed project. In this repo `make lint-rules` passes `--exclude scripts --exclude tests`; `example_app/` and `demo/` are the analyzed code. Single-word function names are not collected (too generic); class, module, package, compound function and compound field names and string literals of 16+ characters are. `example_app` and structural folders are in `generic_names.txt`. | Without `--exclude`, the tooling's own test fixtures (which quote the rules) are reported as leaks. |
| 15 | 3 | `make lint-rules` scans the repo with `--globs '!demo/**'`; `make lint-rules-changed` scans changed files (excluding `demo/`) with `--error`, so `warning` rules fail on new or touched code only. `STAGED=1` switches to staged files; `BASE_REF` overrides `origin/main`, falling back to `main` when there is no remote. | Implements "fail only when a change adds new instances". |
| 16 | 3 | Added `AGENTS.md` with the `rules-table` markers, so `make rules-table` has a target to update. | The plan inserts the table only "if they exist"; one agent file shows the mechanism. |
| 17 | 4 | **Setup is a configurable CLI** (`scripts/setup.py`, stdlib only), at the user's request. It asks which integrations to install (pre-commit, Claude Code hook, Cursor hook, skills) or takes `--with`/`--without`, `--yes`, `--dry-run`, `--uninstall`. JSON files are merged (never overwritten), backed up as `*.bak-<timestamp>` first, and removed on uninstall when nothing else is left. `make setup` runs `uv sync` and the CLI (`SETUP_ARGS` passes flags). `scripts/install_skills.sh` is replaced by the `skills` component (`--skills-scope project|global`). | User decision. One entry point that every developer can tailor. |
| 18 | 4 | The Claude Code hook goes to `.claude/settings.local.json` (personal, gitignored) by default; `--claude-settings project` writes the shared `.claude/settings.json`. `.claude/settings.json` and `.cursor/hooks.json` are therefore not committed; the setup CLI generates them. | Configurable per developer; whoever wants the hook for the whole team commits the project settings. |
| 19 | 4 | Verified the Claude Code hooks schema (code.claude.com/docs/en/hooks): `hooks.PostToolUse[].matcher` + `hooks[].type/command`; exit code 2 shows stderr to Claude; `$CLAUDE_PROJECT_DIR` is exported; user and project hooks both run and identical handlers are deduplicated. **`MultiEdit` no longer exists** (tools reference lists `Edit`, `Write`, `NotebookEdit`), so the matcher is `Edit|Write`. | [VERIFY] item. |
| 20 | 4 | Verified Cursor hooks (cursor.com/docs/agent/hooks): `afterFileEdit` exists but **its output does not reach the agent**. The Cursor hook uses `postToolUse` with matcher `Write` instead, returning findings as `additional_context` (injected after the tool result). As a further fallback, `AGENTS.md` (read by Cursor) asks the agent to run `make lint-rules-changed` before finishing, instead of an `alwaysApply` `.mdc` that would itself need a Checks section. The script reads `tool_input.file_path` (or `path`/`target_file`), because Cursor does not document the `Write` tool input fields. | [VERIFY] item. Not testable end to end without Cursor; the script is tested with a sample payload. |
| 21 | 4 | The rule checks run in pre-commit as a `repo: local` hook (`make lint-rules-changed STAGED=1`, `always_run`), next to the static checks. `boidolr/ast-grep-pre-commit` is not added. | It would run a second, different invocation of the same scan; the plan requires pre-commit and CI to run the same target. |
| 22 | 4 | CI pins `actions/checkout@v5` and `astral-sh/setup-uv@v6` and runs `uv sync --locked`. The `rules` job also runs `make test`. | `act` is not installed on this machine, so the workflow is validated by running each job's commands locally (see README). |
