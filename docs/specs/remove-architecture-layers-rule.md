# Remove the architecture-layers rule

- **Phase:** now
- **Depends on:** none

## Problem

`rules/architecture-layers.mdc` only makes sense inside this repo: its glob is `fixtures/valid/**/*.py` and its bullets name `fixtures.valid.*` modules. `setup-mstack` installs every rule as an always-loaded user rule, so on every machine agents read a rule about fixture modules that don't exist in their project. It is also the only reason this repo needs import-linter, `.importlinter` and two sandbox fixtures in the tests.

## Goal

Remove the rule and every file, test, dependency and line of documentation that exists only for it. Keep import-linter as a **supported tool** in the skills and in `mstack coverage`, because work repos still use it for architecture rules.

## Out of scope

- A generic "repo-only rule" marker for the installer. Revisit it if another repo-specific rule appears.
- Changing `fixtures/valid/`: its `domain/`, `infra/` and `api/` packages still give the other rules realistic code to scan, and `leaking_rule` in the guard tests uses its identifiers.

## Changes

Delete:

- `rules/architecture-layers.mdc`
- `.importlinter`
- `fixtures/invalid/architecture-layers/` (`domain_imports_infra.py`)

Edit:

- `tests/test_checks.py`: remove `DOMAIN_IMPORTS_INFRA`, the exclusion in `AST_GREP_INVALID_FILES` (it becomes every file in `fixtures/invalid/`), `test_lint_imports_passes_on_valid_fixtures` and `test_lint_imports_fails_when_domain_imports_infra`.
- `tests/conftest.py`: remove the `import_linter_sandbox` and `run_lint_imports` fixtures and the now-unused `shutil` import.
- `tests/mstack/guards/conftest.py`: in `rules_sandbox`, drop the `.importlinter` copy.
- `Makefile`: remove `uv run lint-imports` from `guards`.
- `pyproject.toml`: remove `import-linter` from the dev group, then run `uv lock`. If `runtime-lint-command` lands first and makes it a runtime dependency, keep it there: that is for work repos, not this one.
- `README.md`: drop "plus architecture contracts in `.importlinter`" from the `lint/` row, and the `lint-imports` bullet from the `make lint-rules` list.

Add:

- A guard test that keeps the import-linter path in `check_rule_coverage` covered without the real file: write a temporary `.importlinter` with one contract and an `.mdc` whose `## Checks` lists it, then assert `mstack coverage --importlinter <tmp>` passes, and reports `unknown-check` once the contract is removed.

Keep unchanged: `load_import_linter_contracts` in `check_rule_coverage.py`, the import-linter rows in `sync-rules`, `authoring-a-check.md`, `discovery.md`, `rule-format.md` and the reviewer templates, and `import-linter.readthedocs.io` in `generic_names.txt`.

## Tests

- `make test` passes with the import-linter tests removed and the new synthetic coverage test added.
- `make demo` still fails on `fixtures/invalid/` as expected.
- `grep -rn "architecture-layers\|domain-is-pure" .` (excluding `.git` and `CHANGELOG.md`) finds nothing.
